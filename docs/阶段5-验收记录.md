## 本机保存与同步

IndexedDB 分开保存事项缓存、逐条操作队列、元数据、本机访客备份和兼容浏览器的同步租约。数据按访客或账号 ID 隔离；不存密码、会话 Cookie 或验证码。缓存的公开账号资料用于断网重开时找回原账号草稿，上传前仍要重新验证真实服务端会话。

每次输入先写本机，再延迟约 600 ms 提交。未发送的同页修改可合并；一旦请求开始，操作编号、版本及请求内容冻结。上传期间的新输入形成后续操作，前一请求成功只移除自己的队列项。请求已成功但响应丢失时，重开或重试沿用原操作编号，由服务端返回原结果，避免重复新增或重复更新。

离线新增使用浏览器生成的 UUID。年、月、周、日可在离线时关联这些稳定编号；联网按依赖提交，不以临时编号替换关联。队列通过 Web Locks 协调同源页面；不支持该能力时使用 IndexedDB 租约，服务端幂等和账号事务锁继续提供最终约束。

每条操作保留其起始版本。不同事项独立处理，一条冲突不阻塞其余事项；同一事项出现版本冲突时保存本机字段与云端记录，重开仍可选择。若云端已删除，可先复制为新事项或导出，不自动复活被删除数据。被拒绝的非法输入保留在本机，用户修正后重新校验提交。

打开工作台、返回前台、恢复网络、刷新和周期检查会读取云端事项缓存并叠加待提交修改。当前采用账号全量缓存读取、逐事项提交；尚未进行千账号长期数据容量验收。离线或有待提交内容时，统计使用本机完整缓存重新计算并标注来源，权重、周状态映射及关联规则与在线版一致。历史封存、跨年确认和自动顺延仍由服务端执行，离线期间延后到联网补偿；访客不提供云端历史及自动顺延。

正常退出保留所属账号的缓存、待同步队列及冲突，清除当前登录状态；切到其他账号不会展示或上传原账号队列。离线时无法撤销服务端 HttpOnly 会话，退出接口失败会保持当前页面并提示重试。仅未成功落到 IndexedDB 的修改触发关闭页面提醒；已经本机保存的离线队列可关闭后恢复。

生产构建加入最小离线页面壳缓存，使已访问的同源页面断网后能够重新打开；API 从不经过此缓存。首次打开仍需联网，开发模式不注册离线缓存。生产站点需要 HTTPS（localhost 例外）。可安装 PWA、更新体验和移动端进一步优化留到第六阶段。

## JSON 和备份规则

支持原 HTML 导出的 v1/v2 四个数组和新版 v3 格式。旧文件把 `yearId/monthId/weekId/wkStart/wkEnd/due` 转为正式字段；保留层级关联、标题、说明、日期、完成状态、进度和权重。预检拒绝非法日期、错误字段类型、重复 ID、错误层级和超限内容。缺失上级的事项保留并警告为未关联。

单文件最多 5 MiB、10000 条。API 的数据迁移路由及 Nginx 允许 6 MiB 请求，普通业务接口继续限制 32 KiB。服务端不信任文件内账号或版本来覆盖他人数据。追加及文件替换都重新分配 ID，并在事务内重建文件内部关联。

服务端预览有效期 15 分钟，记录账号和当前版本指纹。确认时再次检查版本，期间发生其他设备变更会拒绝并要求重新预检。批量写入、替换前软删除、自动备份、预览标记和幂等回执共同提交；任一步失败整体回滚。导入后的过期未完成事项交给第四阶段顺延服务补偿，保持原始计划和历史来源。

导入、恢复与清空的待确认请求也在发出前写入所属账号的 IndexedDB，同一账号的页面不能覆盖另一批未确认请求。若提交后响应丢失，刷新或关闭重开后可“重试确认上次操作”，仍使用原操作编号读取幂等结果。确认清空前先读取云端实际数量及指纹，确认期间发生变更会拒绝提交。

清空以当前数据指纹为条件，先建立备份，再软删除当前全部事项。云端备份恢复会保留原事项 ID、原关联及完成状态，并递增版本；恢复前再备份当前数据。备份包含回收站与归档事项，历史封存独立保留。界面展示最近 20 份备份，服务端支持分页读取。访客替换、清空和恢复在 IndexedDB 中整体保存备份及事项。

导出及这些业务备份只含四层事项，不是数据库全量备份，不能代替账号、会话、操作历史和封存快照的数据库备份。超过 10000 条时仍可导出和同步；为保证自动备份可恢复，清空或替换会在备份超限时拒绝执行，需先分批整理。预览、备份留存策略及大数据量同步优化在第六阶段容量评估中完善。

浏览器验证使用独立 Chrome 配置目录，不操作用户浏览器。可通过 `CHROME_PATH` 指定 Chrome/Chromium；默认 Windows Chrome 或 Linux `/usr/bin/chromium`，默认访问 `http://localhost:8080`。创建随机测试账号，通过真实 SMTP/Mailpit 注册，结束后清理这些账号的数据；不会清理现有用户。

已完成的本地验证：

- 36 项真实 PostgreSQL / SMTP 集成测试通过，含前三、四阶段回归及第五阶段新增场景。
- 使用原 HTML `sampleState()` 生成的 v2 样本验证 4/6/7/7 数量和完整关联；导入后统计为 31%/66%/50%/0/7，v3 再导出及校验通过。
- 客户端 UUID 的并发重试只创建一次；同 ID 的其他请求不能覆盖；导入的同操作编号重试返回相同结果。
- 非法文件不改变现有记录；过期、跨账号和数据变化后的预览拒绝提交；数据库故障注入证明替换失败会回滚原事项可见性、插入记录、备份、预览状态和操作回执。
- 清空及备份恢复保留原 ID 和关联；导入旧周期未完成事项补偿顺延一次，并保留原计划。
- 生产容器内的 Chrome 实测通过访客示例及重开、确认迁移、实际断网重开、离线新建完整四层链、恢复联网同步、丢失响应重试、上传期间继续输入、持久化版本冲突、不同事项独立同步、清空恢复及账号切换隔离。
- 补充验证关闭原标签并在离线的新标签中重开、新建与失焦保存同时发生、导入响应丢失后重开并确认原操作；恢复旧待办后立即补偿顺延，并回归第四阶段浏览器流程。
- 同一事项冲突测试通过另一请求模拟另一设备的写入，未以两台实体设备测试代替该事实；不同浏览器和实际手机联网兼容性继续纳入最终验收。
