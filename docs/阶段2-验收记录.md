# 第二阶段：四层业务主链与在线保存

日期：2026-10-21。代码目录：`D:/download/ws-p`。本阶段在本地完成，未接入或发布 GitHub 仓库。第三阶段尚未开始。

## 已交付功能

- 年度目标：标题、衡量标准、年份、手动进度、权重。
- 月度目标：标题、说明、所属月份、截止日期、手动进度、权重及年度关联。
- 周任务：标题、说明、自定义起止日期、P0/P1/P2 优先级、未开始/进行中/受阻/已完成状态及月度关联。
- 日待办：标题、执行日期、预计分钟数、完成勾选及周任务关联。
- 支持从父项直接新增下级、回车连续新增、解除或选择上级、搜索其它月份/年份的上级、查看完整来源链。
- 年度/月度双视图和年、月、区间、日期筛选；周任务按日期区间相交检索，支持跨月。列表与关联选择器均可继续加载。
- 行内编辑后经 API 自动保存至 PostgreSQL；逐条显示保存状态，刷新及重新登录后保留数据。
- 同一事项串行提交，保存期间继续输入不会被旧响应覆盖；失败请求可使用原操作编号重试，避免重复新增或提交。
- 同一事项发生版本冲突时，可采用云端内容或保留本次修改；账号隔离及浏览器旧账号请求保护在服务端执行。
- 软删除、分层回收站及恢复。删除父项时保留所有下级，解除直接下级的当前关联，变更日志保留原来源；恢复不自动重接下级。
- 排期可调整，但原始年/月/周区间/执行日期保留。页面支持桌面及手机基础布局。

## 接口与数据约定

所有业务接口均要求有效账号会话。`type` 为 `annual`、`monthly`、`weekly`、`daily`。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/workbench` | 按选定年、月、区间及日期加载四层事项 |
| GET | `/api/work-items/:type` | 分页列表、标题搜索、周期筛选或回收站 |
| POST | `/api/work-items/:type` | 新增事项 |
| PATCH | `/api/work-items/:type/:id` | 按版本更新事项 |
| POST | `/api/work-items/:type/:id/delete` | 软删除并解除直接下级关联 |
| POST | `/api/work-items/:type/:id/restore` | 恢复事项 |

修改、删除与恢复必须提供当前版本；写请求带唯一操作编号。同编号同内容重试返回已保存结果，同编号不同内容拒绝执行。关联校验、版本更新、审计记录与幂等结果在数据库事务中处理。跨账号事项不可读取或修改。

日期字段使用不含时刻的业务日期，避免服务器时区导致日期前移。手动进度不会由下级勾选覆盖。使用第一阶段已建立的业务表，本阶段无需新增数据库迁移，也未修改已应用迁移。

## 本地运行

工作台：[http://localhost:8080](http://localhost:8080)。已登录用户刷新即可加载第二阶段页面；原有账号继续使用。无固定账号密码，可自行注册；本地验证码在 [Mailpit](http://127.0.0.1:8025) 查看。

```sh
docker compose build
docker compose up -d --wait --wait-timeout 120
```

默认应用镜像为 `four-layer-workbench-api:stage2` 和 `four-layer-workbench-web:stage2`。完整初始化、开发及环境配置见项目 README。数据库通过持久卷保存，升级应用无需清空数据库。
