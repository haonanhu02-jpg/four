# 一键部署与重复更新

`deploy/auto-deploy.py` 从本项目 GitHub **最新正式 Release** 下载完整交付包，取得与镜像对应的固定提交源码，通过镜像启动 PostgreSQL、迁移、API 和 Web。再次运行相同命令会检查最新版本并部署，保留原配置、数据库、账号和管理员密码。只有修改源码并正式发布新镜像后，服务器才会更新到该版本；不会把 `main` 的未发布源码与旧镜像混用。

## 环境

- Linux x86_64，或 Windows Docker Desktop 的 Linux 容器模式。
- Docker 已安装并启动，当前用户可以执行 `docker info`；Docker Compose 至少 2.20。
- Python 3.10 或更新版本、curl。运行镜像不需要宿主机 Node.js、npm 或 Git。
- 建议预留至少 4 GB 空间；发布缓存、解压源码、Docker 镜像、数据库和每次升级备份均占用磁盘。已有发布版本默认保留。

脚本不会安装或更改宿主机 Docker，也不会覆盖全局 Git、Docker 镜像源或代理配置。

## 获取脚本

已有源码时直接使用 `deploy/auto-deploy.py`。全新服务器只需下载这一个 Python 文件，不必先克隆完整仓库。Linux 示例：

```sh
curl --fail --location --connect-timeout 5 --max-time 30 \
  'https://ghfast.top/https://raw.githubusercontent.com/haonanhu02-jpg/four/main/deploy/auto-deploy.py' \
  -o auto-deploy.py
```

下载通道不可用时，将前缀替换为 `https://gh-proxy.com/`，或直接使用 `https://raw.githubusercontent.com/haonanhu02-jpg/four/main/deploy/auto-deploy.py`。下载完成后运行 `python3 auto-deploy.py --help` 应显示参数说明。

## 首次启动与以后更新

Linux 本机演练：

```sh
python3 auto-deploy.py --dir "$HOME/four-workbench-deployment"
```

Windows，在源码目录执行：

```powershell
python .\deploy\auto-deploy.py --dir D:\four-workbench-deployment
```

默认访问 `http://localhost:8080`。端口被占用时指定 `--port 18080`，初次生成的本机访问源也会使用该端口。脚本自带 Bash 与 PowerShell 包装器，已有完整源码时也可以运行 `bash deploy/auto-deploy.sh ...` 或 `powershell -File deploy/auto-deploy.ps1 ...`。

**更新时再次执行同一条命令、使用相同 `--dir`。** 不需要手动拉代码、导入镜像、迁移或启动容器。最新版本未变化时复用已校验的下载缓存和本地镜像，并检查服务健康。即使容器已停止，重复运行也会重新启动。

首次创建管理员工号默认 `admin`，密码随机生成，保存到部署目录下 `admin-credentials-随机编号.txt`。密码不会输出到终端。后续运行不重置已有管理员；可通过 `--admin-user` 为尚未创建管理员的环境指定其他工号。初始化中断时，私有文件 `.admin-bootstrap.json` 暂存待完成的凭据，下次运行沿用并验证，成功后移除。

## 对外访问

正式环境示例：

```sh
python3 auto-deploy.py --dir /opt/four-workbench \
  --origin https://workbench.example.com --port 8080
```

把域名解析到服务器，并为该域名配置 HTTPS 反向代理至 `127.0.0.1:8080`。证书及域名属于实际服务器配置，脚本不会猜测或申请。代理配置模板位于发布目录的 `deploy/https.nginx.example.conf`，具体步骤见[生产部署与恢复](生产部署与恢复.md)。脚本成功表示本机服务已健康；域名、证书和公网防火墙还需在实际服务器上接好。

默认仅监听 `127.0.0.1`，适合同主机 HTTPS 代理。需要其他机器的受信代理访问时可指定 `--bind 0.0.0.0` 并限制入口网络。非 localhost 的正式访问源必须为 HTTPS。

## 下载加速与校验

默认顺序为 `ghfast.top` → `gh-proxy.com` → GitHub 官方。每个通道有连接、下载与低速超时；成功后本次运行优先复用该通道。当前公共加速服务可能变更，因此允许覆盖：

```sh
python3 auto-deploy.py --dir /opt/four-workbench \
  --mirror https://你的加速服务域名
```

使用 `--direct` 可只走 GitHub 官方。公共通道只下载公开文件，不发送 GitHub token、数据库密码或管理员信息。加速使用方式见 [GH-Proxy 文档](https://gh-proxy.com/docs/)；latest 资源路径采用 [GitHub 官方约定](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。

一次下载同时取得源码以及 API、Web、PostgreSQL 三个镜像，执行 `docker load` 后通过 `--pull never --no-build` 启动。整个部署过程不需要访问 Docker Hub，也不在服务器执行 npm 安装或构建。

脚本校验完整包 SHA-256、每个交付文件、每个源文件、整体源码指纹以及装载后的镜像标识。兼容 Docker classic 与 containerd 存储方式：只有经归档中 SHA-256 校验过的 OCI 清单与配置关联证明对应同一镜像，才接受不同形式的镜像 ID；不会跳过镜像校验。归档拒绝路径越界、符号链接和特殊文件。散列校验用于检测文件损坏和版本不匹配；需要从独立可信渠道固定包时，可传入该包的 `--sha256 64位校验值`。通过第三方通道取得的清单和散列本身不构成发布者数字签名。

离线部署：

```sh
python3 auto-deploy.py --dir /opt/four-workbench \
  --bundle /path/four-layer-workbench-1.1.0-linux-amd64.tar.gz
```

同目录须有该归档的 `.sha256` 文件，也可显式传 `--sha256`。离线模式只部署指定包；恢复联网检查最新版本时去掉 `--bundle`。需要固定发布版本可用 `--version 1.1.0`。脚本拒绝自动降级，也拒绝自动跨 PostgreSQL 大版本升级。

## 数据、备份和失败处理

部署目录结构：

```text
.env.production           实际随机密钥与运行配置，后续运行复用
state.json                最后一次成功部署的版本与来源
pending.json              尚未成功完成的部署，成功后删除
.env.previous             变更前配置，仅本机保留
previous-state.json       变更前的成功版本记录
downloads/                校验过的下载缓存
releases/版本-包指纹/      镜像、配置、工具和 source/ 源码
backups/                  升级前数据库 dump 与 SHA-256
admin-credentials-*.txt    初始管理员凭据
```

请将整个部署目录保存在同一个固定位置并保护访问权限，尤其不要丢失 `.env.production` 中的数据库密码。首次随机生成密钥，后续从原配置读取；Shell 中的同名环境变量不会覆盖这些配置。发现同项目已有数据卷却缺少原配置时，脚本停止，避免生成不匹配的新密码。

已有实例升级或修改配置前，脚本会启动原数据库并生成一致性 `pg_dump` 备份；备份失败则停止变更。备份会保留，请定期转存到独立存储并按实际保留周期清理。PostgreSQL 数据保存在项目对应的持久卷中，源码缓存或镜像重建不影响该卷。

下载或校验失败时不会更改运行配置、启动新版本。容器启动、迁移或健康检查失败时返回非零退出码，保留 `pending.json`、原配置和数据库备份，不写入成功记录。数据库迁移可能已经执行，因此不会擅自回滚数据库或切换旧镜像。修复网络、端口或运行环境后，使用原命令重试；需要恢复数据库时按[恢复说明](生产部署与恢复.md)在空数据库验证后切换。

脚本具有进程锁，同一目录同时运行只允许一个部署过程；进程异常退出后系统自动释放锁。升级不执行 `down -v`、删除数据卷或 Docker 全局清理，也不更改现有管理员密码。Compose 的启动和就绪语义见 [Docker 官方文档](https://docs.docker.com/reference/cli/docker/compose/up/)。

## 自动定时检查（可选）

“每次运行自动部署”无需额外设置。若需要服务器定时运行，可在自行确定维护窗口后把同一命令加入 cron 或任务计划，例如每天凌晨 3 点；运行账号必须和首次部署使用同一 Docker 环境、具有部署目录权限。此脚本自身不会创建定时任务。
