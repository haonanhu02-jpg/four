# 第三阶段：汇总、年度归集与对齐体检

日期：2026-10-22。代码目录：`D:/download/ws-p`。在本地完成第三阶段，未接入 GitHub 或发布远端。第四阶段尚未开始。

## 功能与口径

| 功能 | 当前行为 |
| --- | --- |
| 年度进度 | 所选年份全部有效年度目标的 Σ（手动进度 × 权重）÷ Σ权重 |
| 月度进度 | 所选月份全部有效月目标按相同规则加权，与截止日独立 |
| 周推进指数 | 与所选区间相交的周任务，按未开始 0、进行中 50、受阻 15、已完成 100 取平均；不代表实际工作量完成率 |
| 日完成率 | 所选日期已完成件数 ÷ 总件数，显示完成数和百分比 |
| 当日焦点 | 所选日期按创建顺序的首个未完成待办，附完整来源链；历史日期标为“当日”，全完成或无待办时明确提示 |
| 计划投入 | 所选日期全部待办的预计分钟数之和，件数和分钟数仅作计划提示 |
| 下级统计 | 年、月卡片分别显示关联下级已完成数 / 总数，保持上层手动进度独立 |

百分比统一由服务端四舍五入。0 权重不参与加权，权重全为 0 时返回空值并显示“未设置权重”；没有目标时显示“暂无目标”。没有周任务或日待办时不虚构 0% 完成率。

概览对全部匹配记录做数据库聚合，不以首页最多 50 条事项代替总量。单个查询内按事项身份计数，跨周、跨月任务在同一范围只计一次。删除或归档的事项不参与统计。

## 年度执行归集

- 按所选年度目标的当前关联链归集月、周、日事项，年度目标本身不计入。
- 包含关联目标下面排在其他月份或跨年的事项，不因后代的排期不同而丢失来源。
- 可筛选年度目标、月/周/日层级、已完成/未完成；每页 20 条，支持前后翻页。
- 按年度目标创建顺序分组，组内月→周→日，再按排期和创建顺序排列。
- 月目标进度 100%、周状态已完成、日待办完成勾选分别定义各层级完成。
- 点击归集记录打开事项详情，可直接编辑或更换关联，沿用版本检查和自动保存。
- 删除父项后，下级保留并解除直接关联；脱离链路的事项从当前归集中移除，历史来源继续保留在已有日志中。封存快照与历史复盘界面属于第四阶段。

例如示例的 6 个月目标、7 个周任务、7 条日待办合计 20 条关联事项，是不同层级对象的数量，不代表 20 个独立成果。

## 对齐体检与修复

| 规则 | 检查范围 / 修复入口 |
| --- | --- |
| 年度目标未拆月目标 | 所选年度，没有任何有效月目标；可新增月目标并自动关联 |
| 月目标未关联年度目标 | 所选月份；打开事项详情选择年度目标 |
| 月目标未拆周任务 | 所选月份，在所选区间内没有相交的周任务；可新增周任务并自动关联 |
| 周任务未关联月目标 | 与所选区间相交；打开详情补充关联 |
| 未完成周任务未安排动作 | 与所选区间相交，在所选区间内没有有效日待办；可直接安排待办并关联 |
| 日待办未关联周任务 | 所选日期；打开详情补充关联 |
| 上层已完成而下层未完成 | 月、周、日的直接上级已完成，当前事项仍未完成；查看并决定调整进度、状态、排期或关联 |
| 逾期未完成 | 所选月目标截止日、周任务结束日、日待办执行日期早于账号今天；已完成事项不报逾期 |

“未拆周任务”和“未安排动作”按所选区间检查，其他区间的旧动作不代替当前安排。逾期相对服务端按用户时区计算的今天判断，不信任浏览器传入的“今天”，也不把查看历史日期当成今天。

问题可按规则筛选并分页。同一事项可以同时触发多个规则，页面分别显示问题数与涉及事项数。没有任何事项时提示先安排目标，不宣称“全部对齐”。未关联事项允许存在，体检不强制改写内容。保存成功后概览、归集和体检自动刷新，失败单独显示可重试提示，不影响事项编辑。

## 新增接口与实现

| 方法 | 地址 | 参数 |
| --- | --- | --- |
| GET | `/api/overview` | `year/month/start/end/date`，返回进度、焦点、来源链、年/月下级统计 |
| GET | `/api/annual-execution` | `year`，可选 `annualId/type/completion/limit/offset` |
| GET | `/api/alignment-check` | `year/month/start/end/date`，可选 `rule/limit/offset` |
| GET | `/api/work-items/:type/:id` | 读取可编辑详情及完整上级链，支持定位未加载或跨期事项 |

接口均基于当前会话限制账号，并检查旧浏览器账号标头。枚举、日期、分页与筛选参数严格校验。读事务使用一致快照，筛选和聚合在 PostgreSQL 执行；前端仅展示服务端结果。没有修改已应用迁移，也无需新增业务表或依赖。
