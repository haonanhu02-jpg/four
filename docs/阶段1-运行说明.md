# 第一阶段运行说明

## 范围

第一阶段提供账号与工程底座：Vue 前端、NestJS API、PostgreSQL、共享接口校验、数据库迁移、密码和验证码登录、验证邮箱注册、密码恢复、退出及账号隔离。数据库已预留四层实体与同步/历史所需结构，四层编辑在第二阶段实现。

## 环境与配置

使用 Node.js 24、npm 11 及已启动的 Docker，Compose v2 或更新版本。先在工程根目录执行：

```sh
node deploy/init-env.mjs
```

该命令读取 `.env.example`，生成随机数据库密码和验证码/令牌密钥，写入未纳入版本管理的 `.env`。它不会覆盖已有文件，也不会打印密钥。已初始化过的工程直接使用原 `.env`。

| 配置 | 用途 |
| --- | --- |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Compose 初始化数据库所用账号、密码和库名 |
| `DATABASE_URL` | npm 本地运行和迁移所用连接字符串，默认端口 15432 |
| `AUTH_TOKEN_SECRET` | 验证码等敏感令牌的摘要密钥，使用随机值且至少 32 字符 |
| `APP_ORIGIN` | npm 本地运行允许的页面来源，开发时设为 `http://127.0.0.1:5173` |
| `COMPOSE_APP_ORIGIN` | 容器运行允许的页面来源，默认 `http://localhost:8080` |
| `COOKIE_SECURE` | 本机 HTTP 用 `false`，正式 HTTPS 设置 `true` |
| `SESSION_TTL_DAYS` | 服务端会话有效天数，默认 7 天 |
| `DB_POOL_MAX` | 单个 API 进程的数据库连接池上限，默认 10 |
| `TRUST_PROXY_HOPS` | npm 直连默认为 0；Compose 在仅内部可访问的 API 前配置一层受信 Nginx，固定为 1，使请求限流能识别客户端地址 |
| `SMTP_HOST` / `SMTP_PORT` | npm 本机 SMTP 地址，默认 `127.0.0.1:1025` |
| `COMPOSE_SMTP_HOST` / `COMPOSE_SMTP_PORT` | 容器内 SMTP 地址，默认 `mailpit:1025` |
| `SMTP_FROM` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` | 发件人、SMTP TLS 和认证配置 |
| `WEB_PORT` / `WEB_BIND_ADDRESS` | 容器前端发布端口与监听地址，默认 `127.0.0.1:8080` |

生成器使用 URL 安全字符生成数据库密码。若手动设置包含 URI 保留字符的密码，`DATABASE_URL` 需要正确编码；Compose 内部连接也应使用经过编码的连接字符串方案。

## 容器运行

```sh
docker compose up -d --build --wait
docker compose ps
```

服务依次为 PostgreSQL 就绪、数据库迁移成功、API 就绪、前端就绪。访问 [http://localhost:8080](http://localhost:8080)。Compose 默认使用本机 Mailpit，邮箱验证码会出现在 [http://127.0.0.1:8025](http://127.0.0.1:8025)。

Mailpit 接收真实 SMTP 消息，但不将邮件发给互联网邮箱。正式邮件投递在配置实际 SMTP 供应商后单独验证。

```sh
docker compose logs --tail=100 api migrate web
docker compose down
```

上述停止命令保留数据库卷。容器重建和应用镜像升级不会删除该卷。数据库密码是初始化时设置的，修改 `.env` 不会自动修改已存在数据库里的密码；已有实例应同步变更数据库密码和应用连接配置。

## 本机开发

```sh
npm ci
docker compose up -d --wait db mailpit
```

把 `.env` 的 `APP_ORIGIN` 改为 `http://127.0.0.1:5173`，再执行：

```sh
npm run db:migrate
npm run dev
```

前端：[http://127.0.0.1:5173](http://127.0.0.1:5173)。API：[http://127.0.0.1:3000/api/health](http://127.0.0.1:3000/api/health)。前端 `/api` 代理默认指向 3000 端口，需要变更时配置 `API_PROXY_TARGET`。

迁移会验证已执行 SQL 文件的校验和，用数据库锁协调多进程，并逐个事务执行新迁移。后续变更新增迁移文件，已执行文件保留不变。

## 账号验收

1. 打开注册页，输入邮箱并发送验证码。
2. 在 Mailpit 中读取验证码，完成注册后确认账号区显示该邮箱。
3. 退出，以密码登录；再退出，以验证码登录。
4. 使用密码恢复流程修改密码，确认旧密码无法登录。
5. 创建第二个账号，检查账号区和计数仅反映当前账号的数据。
6. 验证无登录请求不能访问账号接口，错误验证码、过期验证码和重复消费返回明确错误。

不使用开发固定验证码或伪造登录。验证码不通过业务 API 返回，浏览器不保存可读取的会话令牌。短信登录和组织共享不属于当前阶段。

## 检查与持续集成

```sh
npm run check
npm run db:migrate
npm run test:integration
docker compose build
```

GitHub Actions 构建隔离环境，启动 PostgreSQL/Mailpit、迁移、代码与类型检查、构建、集成测试、镜像构建及容器 HTTP 就绪检查。流程不向镜像仓库推送，也不部署远端。

## 正式环境配置要点

正式部署使用 HTTPS，对应配置 `COOKIE_SECURE=true` 和实际 `COMPOSE_APP_ORIGIN`。提供真实 SMTP 配置，并将数据库和 SMTP 凭据通过部署环境注入。共享服务器按实际反向代理调整 `WEB_BIND_ADDRESS`；数据库端口仍只对本机开放。

当前 Compose 是第一阶段可运行配置。最终阶段补齐容量验证、发布镜像归档、备份恢复演练及完整升级回退记录。不要将“Dockerfile 已有”视为最终生产验收完成。
