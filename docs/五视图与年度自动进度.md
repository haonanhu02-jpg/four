# 五视图与年度自动进度

2026-11-04，工程版本 1.2.0。本次沿用 Vue、NestJS、PostgreSQL、IndexedDB 与 Docker 部署，新增迁移 `0007_five_views.sql`，不修改已执行的迁移。

## 页面使用

| 视图     | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 年度目标 | 表格直接编辑目标、衡量标准、权重、预计完成日期、进度模式；保留年度执行归集与对齐体检 |
| 月度执行 | 表格编辑月目标、年度关联、权重、截止日期、手动进度；保留对齐体检                     |
| 周任务   | 自定义区间按交集展示；每日工作按所属周任务和日期分组，可单条或全部展开/收起          |
| 图表看板 | 年度进度对比、状态环图、12个月目标当前进度、本月目标对比；可点击目标打开详情         |
| 清单     | 年→月→周→日逐层展开，按完成情况、关键词筛选；保留上级路径，点击标题可编辑详情        |

手机下目标表格转换为带字段标签的卡片，日期、上级选择器与树形缩进适配窄屏。深浅色共用现有主题变量。各账号的最后使用视图在本机独立保存。

周任务的每日工作展示所有关联日期，包括所选区间以外的记录，以便追溯；卡片保留原排期和顺延次数。本区间日待办的周任务来源若在区间外，会标注“区间外周任务来源”并补充展示；没有有效周任务来源的日待办在“未关联周任务的每日工作”单独展示，可补充关联。新增和修改仍通过原保存队列，不另存一份数据。

## 年度进度规则

- 每个年度目标可在“手动填写”和“月目标自动汇总”之间切换，现有目标默认手动。
- `progress` 始终保存原手动值，`progressMode` 保存选择。自动模式读取时计算，不覆盖手动值，不对月目标重新排期，也不批量改写上级事项。
- 自动进度 = 四舍五入（Σ有效下属月目标进度×权重 / Σ权重）。包含当前年度目标下跨月、跨年排期的月目标；排除删除、归档和零权重月目标。
- 无下属月目标或有效权重为零时，自动进度为 0%。切回手动立即使用原手动值。
- 年度概览和图表使用各年度目标当前模式的进度，再按年度权重加权。年度权重全零时概览显示“—”；月度权重按实际总和归一，无需强制合计 100%。
- 月度目标保持手动进度；周推进指数仍按状态 0/50/15/100 平均；日完成率仍按件数，不反推月进度。
- 12个月图显示各月份现有目标的当前加权进度，不是历史时点趋势。历史时点数据仍到“历史复盘”查看。
- 封存年度时冻结当时自动计算值，保留当时手动值和模式；之后修改月目标不会改写已封存记录。

## 新增字段与兼容

年度增加 `progressMode`、`dueDate`；每日增加 `time`、`note`。时间原文支持填写时间段、小时或分钟；可解析的时长仅辅助显示，不覆盖单独填写的预计分钟数。工作情况允许多行。

JSON v3、Excel、Word 表格和 TXT 表格均携带新增字段。旧 JSON v1/v2 继续支持，折叠版导出的年度 `due`、每日 `time` 和 `note` 会保留。没有进度模式的旧文件按手动导入。Word 正文和普通 TXT 每段/行作为一条日待办的规则保持。

原有工号登录、旧账号、管理员及管理日志、备份与回收站、离线草稿、账号隔离、版本冲突处理、顺延和跨年承接继续使用原实现。清单展示跨年来源，并为未关联或来自其他年度的本年度排期单列分组，避免事项因缺少上级而不可见。

## 验证

`npm run check` 执行代码、类型和构建检查；`npm run test:integration` 包含进度切换、跨年下属、零权重、删除恢复、文件转换、新字段备份恢复及历史冻结检查。

`npm run test:views` 使用真实 Chrome 验证五视图、内嵌每日工作、自动/手动切换、统计一致性、清单搜索与详情、刷新后保留及两种主题在 1440/390 像素下的布局。

原有 `test:browser`、`test:ui`、`test:features` 已适配新导航；管理员和 Office 验证在隔离 QA 数据库执行。截图及验证产物位于 `artifacts/five-views/`，不进入源码和镜像。

本地升级前已创建 PostgreSQL 自定义格式备份，并验证可读取目录。Docker 和一键部署流程沿用原有机制；正式 Release 附件与版本不会被本地改版覆盖。
